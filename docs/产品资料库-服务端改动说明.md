# 产品资料库 — 服务端改动说明

> **背景**：客户端产品资料库原先直连旺店通 ERP 并在本地 JSON 文件存储数据。  
> 现已改造为：**所有存储迁移到服务端**，客户端通过 HTTP 接口操作数据，以**机器码**（16 位 hex）作为客户端唯一标识。  
> 本文档描述服务端需要新增/改造的接口与存储逻辑。

---

## 一、整体架构

```
客户端（PySide6 GUI）
   │
   │  X-Machine-ID: a1b2c3d4e5f60718
   │
   ▼
服务端（FastAPI）
   │
   ├── /api/product-library/clients/{machine_id}/...   ← 新增：按机器码隔离的 CRUD
   │
   ├── /api/product-library/sync                        ← 保留：ERP 同步触发（可选保留全局或改为按 machine_id）
   │
   └── 存储层（PostgreSQL / SQLite / JSON）              ← 每条产品记录关联 machine_id
```

### 1.1 机器码（machine_id）

- 由客户端 `utils/license.py` 的 `get_machine_id()` 生成
- 算法：`SHA256(MAC + 主机名 + CPU + 主板UUID)[:16]` → 16 位十六进制字符串
- 同一台物理机始终返回相同值，跨机器唯一
- 客户端在 **每个请求的 URL 路径** 和 **`X-Machine-ID` Header** 中携带

### 1.2 存储隔离原则

- 服务端按 `machine_id` 隔离每台客户端的产品资料
- 不同 `machine_id` 的数据完全独立（类似多租户）
- 建议存储方式：在 `product_items` 表中增加 `machine_id` 列作为联合主键/索引

## 二、新增接口：客户端 CRUD（按机器码隔离）

### 基础路径

```
/api/product-library/clients/{machine_id}
```

`machine_id` 为 16 位十六进制字符串（如 `a1b2c3d4e5f60718`）。

### 2.1 获取全部产品

```
GET /api/product-library/clients/{machine_id}/items
```

**Query 参数：** 无

**响应：**

```json
{
  "ok": true,
  "items": [
    {
      "id": "server_generated_id",
      "category": "鼠标",
      "brand": "罗技",
      "model": "G PRO X SUPERLIGHT 2",
      "goods_no": "LG-GPXSL2",
      "spec_no": "LG-GPXSL2-BK",
      "spec_name": "黑色",
      "barcode": "6970986123456",
      "stock_num": "128",
      "available_num": "115",
      "warehouse": "主仓、华东仓",
      "notes": "",
      "features": "- 重量：60g",
      "selling_points": "- 超轻设计",
      "created_at": 1751900000,
      "updated_at": 1752050000
    }
  ]
}
```

**产品条目字段（所有接口共用）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 服务端生成的唯一 ID |
| `category` | string | 品类 |
| `brand` | string | 品牌 |
| `model` | string | 型号/货品名称 |
| `goods_no` | string | 商家编码 |
| `spec_no` | string | 规格编码（SKU 唯一键） |
| `spec_name` | string | 规格名称 |
| `barcode` | string | 条形码 |
| `stock_num` | string | 库存量 |
| `available_num` | string | 可用库存 |
| `warehouse` | string | 仓库（多仓用「、」分隔） |
| `notes` | string | 备注 |
| `features` | string | 性能参数（Markdown） |
| `selling_points` | string | 核心卖点（Markdown） |
| `created_at` | int | 创建时间（Unix 时间戳） |
| `updated_at` | int | 最后更新时间（Unix 时间戳） |

### 2.3 新增产品

```
POST /api/product-library/clients/{machine_id}/items
Content-Type: application/json
```

**请求体（产品字段，不含 id/时间戳）：**

```json
{
  "category": "鼠标",
  "brand": "罗技",
  "model": "G502",
  "goods_no": "...",
  "spec_no": "...",
  "spec_name": "...",
  "barcode": "...",
  "stock_num": "...",
  "available_num": "...",
  "warehouse": "...",
  "notes": "...",
  "features": "...",
  "selling_points": "..."
}
```

**服务端逻辑：**

1. 校验必填字段：`brand` 和 `model` 不能为空
2. 查重：按 `spec_no`（优先）或 `brand + model` 查找是否已存在
   - 已存在：返回 409 或 `{"ok": false, "message": "已存在相同 规格编码 或 品牌+型号 的其它条目，请改用编辑。"}`
3. 生成 `id`（16 位 hex）和 `created_at` / `updated_at`
4. 存储并关联 `machine_id`

**成功响应：**

```json
{
  "ok": true,
  "message": "已添加。",
  "item": { "id": "xxx", "category": "鼠标", ... , "created_at": 1752000000, "updated_at": 1752000000 }
}
```

---

### 2.4 修改产品

```
PUT /api/product-library/clients/{machine_id}/items/{item_id}
Content-Type: application/json
```

**请求体：** 同新增（不含 id/时间戳）

**服务端逻辑：**

1. 校验必填字段
2. 查重（排除自身）
3. 更新字段 + 刷新 `updated_at`

**成功响应：**

```json
{
  "ok": true,
  "message": "已保存。",
  "updated_at": 1752100000
}
```

---

### 2.5 删除产品

```

```

**成功响应：** HTTP 200 + `{ "ok": true }`

**不存在：** HTTP 404 + `{ "detail": "条目不存在" }`

## 三、新增接口：批量操作

### 3.1 批量 upsert（仓库同步/Excel 导入）

```
POST /api/product-library/clients/{machine_id}/upsert
Content-Type: application/json
```

**请求体：**

```json
{
  "items": [
    { "category": "鼠标", "brand": "罗技", "model": "G502", "spec_no": "...", ... },
    { "category": "键盘", "brand": "雷蛇", "model": "黑寡妇", "spec_no": "...", ... }
  ]
}
```

**服务端逻辑：**

对每个 item：
1. 按 `spec_no`（优先）或 `brand + model` 查找该 `machine_id` 下是否已有同条目
2. **已存在**：仅更新 `WAREHOUSE_FIELDS`（brand, goods_no, spec_no, spec_name, barcode, stock_num, available_num, warehouse），保留 `category`/`notes`/`features`/`selling_points`/`model` 不变
3. **不存在**：新增，生成 `id` + 时间戳

> `WAREHOUSE_FIELDS` = `("brand", "goods_no", "spec_no", "spec_name", "barcode", "stock_num", "available_num", "warehouse")`

**响应：**

```json
{
  "ok": true,
  "added": 5,
  "updated": 120
}
```

---

### 3.2 批量补全品类（apply_categories）

```
POST /api/product-library/clients/{machine_id}/apply-categories
Content-Type: application/json
```

**请求体：**

```json
{
  "goods_map": {
    "LG-GPXSL2": { "category": "鼠标", "brand": "罗技" },
    "RS-BWV4": { "category": "键盘", "brand": "雷蛇" }
  },
  "fill_brand_if_empty": true
}
```

**服务端逻辑：**

对该 `machine_id` 下的每条产品：
1. 按 `goods_no` 在 `goods_map` 中查找
2. 若产品的 `category` 为空且 `goods_map` 有 `category` → 填充
3. 若 `fill_brand_if_empty=true` 且产品的 `brand` 为空 → 填充
4. 有改动则刷新 `updated_at`

**响应：**

```json
{
  "ok": true,
  "updated": 42
}
```

## 五、改造接口：ERP 同步（按机器码隔离）

### 5.1 触发同步

```
POST /api/product-library/clients/{machine_id}/sync
```

**服务端逻辑：**

1. 用服务端持有的旺店通 ERP 凭据拉取库存 + 货品档案
2. 映射 + 聚合为产品条目
3. 按 `machine_id` 执行 upsert（同 §3.1 逻辑）
4. 自动补全品类（同 §3.2 逻辑）
5. 全部在后台异步执行

**响应（立即返回）：**

```json
{ "ok": true, "message": "同步已启动" }
```

**冲突（已有同步任务在跑）：**

HTTP 409：
```json
{ "detail": "同步正在进行中，请等待完成" }
```

---

### 5.2 查询同步进度

```
GET /api/product-library/clients/{machine_id}/sync/status
```

**响应：**

```json
{
  "running": true,
  "phase": "正在获取品类... 已识别 42 个货品",
  "fetched": 800,
  "total": 1526,
  "added": 120,
  "updated": 680,
  "error": "",
  "started_at": 1752100000,
  "finished_at": 0
}
```

| 字段 | 说明 |
|------|------|
| `running` | 是否正在运行 |
| `phase` | 当前阶段描述 |
| `fetched` / `total` | 已拉取 / 总记录数 |
| `added` / `updated` | 新增 / 更新条数 |
| `error` | 错误信息（空字符串=无错误） |
| `started_at` / `finished_at` | 开始/结束时间戳（Unix） |

## 六、存储层建议

### 6.1 数据库表结构（PostgreSQL / SQLite 参考）

```sql
CREATE TABLE product_items (
    machine_id  VARCHAR(16) NOT NULL,
    id          VARCHAR(32) NOT NULL,
    category    TEXT DEFAULT '',
    brand       TEXT DEFAULT '',
    model       TEXT DEFAULT '',
    goods_no    TEXT DEFAULT '',
    spec_no     TEXT DEFAULT '',
    spec_name   TEXT DEFAULT '',
    barcode     TEXT DEFAULT '',
    stock_num   TEXT DEFAULT '',
    available_num TEXT DEFAULT '',
    warehouse   TEXT DEFAULT '',
    notes       TEXT DEFAULT '',
    features    TEXT DEFAULT '',
    selling_points TEXT DEFAULT '',
    created_at  INTEGER NOT NULL,
    updated_at  INTEGER NOT NULL,
    PRIMARY KEY (machine_id, id)
);

CREATE INDEX idx_product_items_machine ON product_items(machine_id);
CREATE INDEX idx_product_items_spec ON product_items(machine_id, spec_no);
CREATE INDEX idx_product_items_brand_model ON product_items(machine_id, brand, model);
```

### 6.2 同步状态表（可选，也可用内存/Redis）

```sql
CREATE TABLE product_sync_status (
    machine_id  VARCHAR(16) PRIMARY KEY,
    running     BOOLEAN DEFAULT FALSE,
    phase       TEXT DEFAULT '',
    fetched     INTEGER DEFAULT 0,
    total       INTEGER DEFAULT 0,
    added       INTEGER DEFAULT 0,
    updated     INTEGER DEFAULT 0,
    error       TEXT DEFAULT '',
    started_at  INTEGER DEFAULT 0,
    finished_at INTEGER DEFAULT 0
);
```

## 九、注意事项

1. **鉴权**：当前所有 `/api/product-library/` 前缀已在服务端中间件白名单中放行，无需额外鉴权。
2. **并发控制**：同步接口同一 `machine_id` 同一时间只允许一个任务（409 冲突）。
3. **幂等性**：upsert 操作是幂等的（以 `spec_no` 或 `brand+model` 为唯一键）。
4. **数据迁移**：如果服务端之前已有全局产品数据（非按 machine_id 隔离），需将旧数据迁移到某个默认 machine_id 下，或让各客户端首次同步时重新拉取。
5. **超时建议**：
   - CRUD / 查询类：10s
   - 批量 upsert / apply-categories：30-60s
   - ERP 同步触发：10s（异步，立即返回）
   - 同步进度查询：10s
