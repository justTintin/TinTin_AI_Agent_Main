# 客户端轻量化方案：剩余模型调用全部服务端化

> 目标：客户端只保留 UI 渲染 + ffmpeg/ffprobe 级轻量预处理，所有 AI 模型推理统一由算力服务端执行。
>
> 版本分支：V1.0.7.22　|　日期：2026-08-10

---

## 一、现状盘点

### 1.1 已服务端化（无需改动）

| 文本/视觉 LLM | `utils/llm_proxy.py`（llm_chat / llm_chat_messages） | `POST /llm/chat/completions`（服务端持 Key、按 model 路由） |

| # | 功能 | 位置 | 现状 |

## 二、迁移方案

### 2.A rembg 抠图 → 服务端 `POST /material/matting`（唯一需要服务端新增接口的项）

**服务端改动**：

```
POST /material/matting
Content-Type: multipart/form-data
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| file | binary | ✅ | — | 待抠图片（png/jpg，multipart/form-data） |
| model | string | ❌ | u2net | 模型名：u2net / isnet-general-use / u2net_human_seg |
| alpha_matting | boolean | ❌ | false | 是否启用 alpha matting 精细化 |

**响应**：直接返回 PNG 二进制（`Content-Type: image/png`），同步模式（单图推理 < 5s，无需任务队列）。

服务端实现要点：
- 复用 `rembg` 库（`new_session(model)` + `remove()`），session 按 model 缓存，避免重复加载；
- 模型文件放服务端统一目录，客户端不再需要下载 `u2net.onnx`；
- 并发控制：单 GPU/CPU 串行队列或信号量限流。

**客户端改动**：

1. 新增 `studio/utils/matting_client.py`：
   ```python
   def matting_image(file_path, model="u2net", out_path="", server_url="") -> str:
       """上传图片到服务端 /material/matting，保存返回的透明 PNG，输出路径。"""
   ```
   复用 `ocr_client.py` 的 `_server_url()` 模式（读 `compute_server_url`）。
2. `image_matting_page.py::RembgWorker.run()`：删除 `sys.path.insert` / `U2NET_HOME` / `from rembg import remove` 逻辑，改为调用 `matting_image()`；进度提示改为"正在上传服务端抠图…"。
3. `cover_maker_page.py::RembgWorker`：同样替换（两处共用则抽到 `matting_client`）。
4. 模型下拉框保留（u2net / isnet…），值透传给服务端 `model` 参数。

### 2.B LocalVisionDescWorker → 统一 LLM 代理

**问题**：该 Worker 客户端逐镜头抽帧、base64 后直连 Ollama（`llm_vision_api_url` 或 11434），绕过统一代理，且上传流量大。

**方案（分两步）**：

- **第一步（零服务端改动）**：将每镜头的「帧图 + 提示词」调用改为 `llm_chat_messages`（服务端 `/llm/chat/completions` 已支持多模态 content 与 Ollama 视觉模型路由，`hook_score_page`/`video_ai_rename_page` 已验证此路径）。删除直连 Ollama 的 HTTP 代码，`llm_vision_api_url` 配置项仅保留给「Ollama 状态检测」展示。
- **第二步（可选，服务端新增批量接口）**：新增 `POST /material/describe_shots`（多文件上传 + 可选 srt），服务端自己抽帧 + 视觉描述，一次性返回 `{"1": "desc", ...}`；客户端不再抽帧、不再传 base64。此接口同时用于补齐 **D** 项缺失的 `describe_shots` 实现。

### 2.C storyboard 相似度检索 → `POST /material/search`

`_SimilarSearchWorker.do_work()` / `_AutoBindShotsWorker.do_work()` 中的 `search_by_text(...)` 替换为服务端检索：

```python
resp = requests.post(f"{server_url}/material/search",
                     json={"query": q, "limit": top_k}, timeout=30)
rows = resp.json().get("results", [])
```

字段映射：`path/filename/brand/model/score` 与现有 UI 展示字段对齐；服务端未配置时 emit error 提示"请先配置算力服务端地址"。

### 2.D 补齐 `utils/montage_client.py`

新建 `studio/utils/montage_client.py`，实现 `describe_shots(clip_paths) -> dict`：
- 一期：逐条走 `ServerClipAnalysisWorker` 同款 `/material/score_clip`（`analyze_shot=true`）取 `description`；
- 二期：服务端落地 `/material/describe_shots` 后切换为批量接口。

### 2.E VSR 去字幕切换服务端（✅ 已实施，2026-08-11）

`subtitle_removal_page*.py` 由「子进程调用 `apps/vsr-v1.x` 本地 exe」改为：
`POST /vsr/remove`（file + inpaint_mode + sub_areas）→ 轮询 `GET /tasks/unified/{task_id}` → `GET /vsr/download/{filename}` 下载结果视频。
接口已在 SERVER_API.md §七 定义，属纯客户端切换。OCR 字幕检测已走服务端 `/material/ocr`，无需再动。

**实施结果**：新增 `studio/utils/vsr_client.py`（`vsr_remove_remote`）；两个去字幕页面新增「使用服务端处理」开关且默认勾选，结果直接落盘本地 `原名_no_sub.mp4`；本地模式保留作回退；路由连通性已验证，待实际视频端到端验证后可移除 `apps/vsr-*` 目录。

### 2.F 顺手修复隐藏 Bug

`desc_workers.py` L115 `log.info(f"...API: {url}...")` → 删除 `{url}` 引用（该变量已随服务端化移除），避免 `BatchGenerateDescriptionsWorker` 运行必崩。
