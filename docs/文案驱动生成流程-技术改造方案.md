# 智能混剪「文案驱动」生成流程 · 技术改造方案

> 需求编号：#31 ｜ 定位：**独立新流程**，现有「成片优先」四步流程零改动
>
> 关联：`二期开发文档-客户端轻量化.md` §10.1、`需求以及bug修改.md` #31、`SERVER_API.md`

---

## 一、方案概述

### 1.1 目标

在**不改动现有四步流程**的前提下，新增一条「文案驱动」的独立混剪流程：先产出文案，再由文案驱动生成音频与视频，最终音画对齐合成。

### 1.2 与现有流程的关系

| | 现有流程（成片优先，保留不动） | 新增流程（文案驱动，独立） |
|---|---|---|
| 步骤 | 分割→重组→配音→包装 | 分割→文案→音视频生成→对齐合成 |
| 驱动源 | 视频成片 | 文案 |
| 音画对齐方向 | 音频变速贴视频 | **视频时长贴音频** |
| 入口 | 现有步骤条 | 新增独立入口/模式 |

> 两条流程**共用底层能力**（分割、描述、TTS、拼接、混音 Worker），但**步骤视图与编排相互隔离**，互不影响。

### 1.3 总体流程

```
素材导入
   │
① 镜头智能分割（复用现有分割 + 逐镜头描述 + 评分）
   │  产出：镜头片段列表 + 每镜头画面描述 + 评分
   ▼
② 文案生成 / 编辑（新）
   │  基于镜头描述 + 产品提示词 AI 生成口播文案（每行一句），用户可编辑/增删/排序
   ▼
③ 文案 → 音频（新）
   │  文案逐行 TTS，得到每行配音 wav + 真实时长（句级时间轴）
   ▼
④ 文案 → 视频（新）
   │  以文案行为单位匹配最佳镜头，镜头呈现时长 = 对应行音频时长
   ▼
⑤ 音画对齐合成（新）
      以文案句为时间轴骨架：拼接视频 + 叠加配音 + 烧字幕 + BGM → 成片
```

## 二、现状能力盘点（可复用）

改造**优先复用**现有构件，避免重复造轮子：

| 能力 | 现有载体 | 复用方式 |
|------|---------|---------|
| 镜头分割 | `split_workers.py`、step1 分割逻辑 | 直接复用 |
| 逐镜头画面描述 | `montage_client.describe_shots()`（服务端 `/material/score_clip`） | 直接复用 |
| 文案生成（按镜头） | `script_workers.GenScriptWorker` | **核心复用**，本就是为「按文案匹配」设计 |
| 产品/场景文案 | `script_workers.ProductCopyWorker` / `SceneCopyWorker` | 复用 |
| 文案→镜头匹配 | `script_workers.ScriptMatchLLMWorker`（LLM 返回 line→shot JSON） | **核心复用** |
| TTS 配音 | `voice_workers.VoiceCloneWorker`（逐句合成 + `.timing.json` 句级时间轴 + atempo 变速） | **核心复用** |
| 视频拼接/转场 | `concat_workers.VideoConcatWorker._concat_with_transition`（xfade） | 复用（改造时长控制） |
| BGM 混音（人声闪避） | `concat_workers.FinalMixWorker`（amix + duck） | 复用 |
| 配音烧字幕 | `concat_workers.VideoDubbingWorker`（add_subtitles） | 复用 |
| LLM 代理 | `llm_proxy.llm_chat / llm_chat_messages / llm_chat_json` | 复用 |
| CLIP 语义检索 | 服务端 `/material/search`（storyboard 已用） | 匹配增强（可选） |
| 音频时长探测 | `utils_media.get_media_duration` / `find_ffmpeg` | 复用 |

**关键洞察**：`VoiceCloneWorker` 已实现「逐句 TTS + 每句真实时长写入 `.timing.json`」，这正是音画对齐与字幕对轴所需的时间轴基础；只需把「对齐方向」从「音频贴视频」反转为「视频贴音频」。

## 三、总体架构设计

### 3.1 独立编排控制器

新增独立控制器 `ScriptDrivenMontageController`（参考现有 `beat_montage_controller.py` 的模式），持有新流程自己的状态与步骤栈，**不复用** `VideoMontagePage` 的 `stacked_widget` 步骤索引，从根上隔离。

```
studio/gui/montage/
├── script_driven_controller.py      # 【新增】文案驱动流程编排控制器
├── sd_step_split_view.py            # 【新增】SD-步骤1 分割（薄封装现有分割）
├── sd_step_script_view.py           # 【新增】SD-步骤2 文案生成/编辑
├── sd_step_generate_view.py         # 【新增】SD-步骤3 音视频生成（TTS + 镜头匹配）
├── sd_step_compose_view.py          # 【新增】SD-步骤4 音画对齐合成
└── workers/
    └── sd_workers.py                # 【新增】文案驱动专用 Worker（匹配编排 + 时长适配 + 对齐合成）
```

> 命名前缀 `sd_`（script-driven）与现有 `step1~step4` 明确区分，杜绝误改现有文件。

### 3.2 入口与模式选择

- 在混剪页面顶部（或新建任务入口）新增**流程选择**：`成片优先（默认）` / `文案驱动`
- 选择「文案驱动」→ 由 `ScriptDrivenMontageController` 接管，展示独立的 SD 步骤条与步骤视图
- 选择「成片优先」→ 走现有 `VideoMontagePage` 逻辑，**完全不变**
- 两套流程的中间产物目录隔离（如 `outputs/montage_scriptdriven/` vs `outputs/montage/`）

### 3.3 步骤定义

| SD 步骤 | 名称 | 输入 | 输出 |
|--------|------|------|------|
| SD-1 | 镜头智能分割 | 素材目录 | 镜头片段 + 描述 + 评分 |
| SD-2 | 文案生成/编辑 | 镜头描述 + 产品提示词 | 口播文案（分句行） |
| SD-3 | 音视频生成 | 文案行 + 镜头池 | 每行配音 wav + 匹配镜头 + 时长 |
| SD-4 | 音画对齐合成 | 时间轴数据 | 成片 mp4 |

## 四、步骤视图设计

### 4.1 SD-1 镜头分割视图（`sd_step_split_view.py`）

- 薄封装现有分割能力：选择素材 → 场景分割 → 生成每镜头描述 + 评分
- 表格列：序号 / 片段预览 / 时间戳 / 画面描述 / 评分 / 时长
- 「下一步：生成文案」携带镜头列表进入 SD-2
- 复用 `split_workers.py` 与 `describe_shots()`，不改现有 step1

### 4.2 SD-2 文案生成/编辑视图（`sd_step_script_view.py`）

- **输入区**：产品提示词（品牌/品类/型号/卖点）、目标总时长、语速基准
- **生成**：调 `GenScriptWorker`（镜头描述 + 产品背景 + 时长 → 每行一句文案）
- **编辑器**：可编辑的多行文案表格，每行显示：行号 / 文案文本（可编辑）/ 预计字数 / 对应镜头（占位，SD-3 填充）
- 支持：增行 / 删行 / 上下移动 / AI 改写（复用 `BatchAITextRewriteWorker`）
- 「下一步：生成音视频」携带最终文案行进入 SD-3

### 4.3 SD-3 音视频生成视图（`sd_step_generate_view.py`）

- 一键执行两件事（可分步触发）：
  1. **文案→音频**：逐行 TTS（`VoiceCloneWorker`），每行得到 wav + 时长
  2. **文案→视频**：为每行匹配镜头（`ScriptMatchLLMWorker` + 可选 CLIP），并按音频时长适配镜头
- 表格列：行号 / 文案 / 配音时长 / 匹配镜头 / 镜头原时长 / 适配方式 / 试听 / 预览 / 手动改配
- 允许用户**手动调整**某行匹配的镜头（下拉/弹窗选择）
- 「下一步：合成」携带时间轴进入 SD-4

### 4.4 SD-4 音画对齐合成视图（`sd_step_compose_view.py`）

- 展示最终时间轴（每行：文案 / 镜头 / 起止时间 / 时长）
- 选项：字幕开关（用 `.timing.json` 生成 SRT/ASS）、BGM 选择 + 人声闪避、转场类型、输出分辨率/编码
- 「开始合成」→ `SDComposeWorker` → 成片预览 + 导出
- 复用 `FinalMixWorker`（BGM 混音）与 `VideoDubbingWorker`（烧字幕）

## 五、文案-镜头匹配算法

### 5.1 匹配策略（三级）

1. **LLM 语义匹配（主，复用 `ScriptMatchLLMWorker`）**
   - 输入：文案行列表 + 候选镜头（文件名 + 画面描述）
   - 输出：JSON `[{line_index, best_match_shot_index}]`
   - 优点：理解语义与叙事顺序；现有实现可直接复用
2. **CLIP 向量匹配（增强，可选）**
   - 文案行文本 → CLIP text embedding；镜头描述/关键帧 → CLIP image/text embedding
   - cosine 相似度召回 top-k，作为 LLM 匹配的候选约束或交叉验证
   - 复用服务端 `/material/search`
3. **顺序/规则兜底**
   - 当描述缺失或 LLM 失败：按镜头原始顺序依次分配

### 5.2 约束与去重

- **去重优先**：默认一个镜头只分配给一行；镜头数 ≥ 文案行数时可完全去重
- **镜头不足**：允许高质量镜头复用，但避免相邻两行用同一镜头
- **评分加权**：优先分配评分高的镜头（复用 SD-1 的评分）
- **手动覆盖**：用户手动指定的匹配优先级最高，锁定不被自动匹配覆盖

### 5.3 匹配结果数据结构

```python
MatchResult = {
    "line_index": int,          # 文案行号（0 起）
    "text": str,                # 文案文本
    "clip_path": str,           # 匹配到的镜头文件
    "clip_desc": str,           # 镜头描述
    "score": float,             # 镜头评分
    "confidence": float,        # 匹配置信度（0~1）
    "locked": bool,             # 是否用户手动锁定
}
```

## 六、音画对齐时间轴（核心）

### 6.1 对齐方向反转

| | 现有流程 | 新流程 |
|---|---|---|
| 基准 | 视频时长固定 | **音频时长固定**（TTS 自然语速） |
| 适配对象 | 音频 atempo 变速贴视频 | **视频镜头时长贴音频** |
| 风险 | 变速过大失真 | 镜头过短需补足 |

新流程中**不再对配音做大幅变速**（保持自然语速），改为调整镜头呈现时长。

### 6.2 时间轴模型

以文案句为骨架，逐行累加得到全局时间轴：

```python
TimelineEntry = {
    "line_index": int,
    "text": str,
    "audio_path": str,      # 该行配音 wav
    "audio_dur": float,     # 配音真实时长（TTS 产出）
    "clip_path": str,       # 匹配镜头
    "clip_start": float,    # 镜头截取起点（相对镜头源）
    "clip_dur": float,      # 镜头呈现时长（= 目标时长）
    "adapt_mode": str,      # trim / slow / loop / still（见 6.3）
    "t_start": float,       # 全局起点（累加）
    "t_end": float,         # 全局终点
}
```

全局 `t_start/t_end` 由 `audio_dur`（可加句间间隙 gap）逐行累加；字幕对轴直接复用每行 `audio_path` 的 `.timing.json`。

### 6.3 镜头时长适配策略

目标：让镜头呈现时长 `= audio_dur`。设镜头原时长 `clip_src_dur`：

| 情况 | 策略 | ffmpeg 实现 |
|------|------|------------|
| `clip_src_dur ≥ audio_dur` | **裁剪 trim**：截取 `audio_dur` 秒（默认居中或取前段） | `-ss X -t audio_dur` |
| `clip_src_dur < audio_dur` 且差距小 | **降速 slow**：放慢至 `audio_dur`（限幅 ≤1.5x，避免过慢） | `setpts=PTS*ratio`（+ 音频分离，无原声则无影响） |
| `clip_src_dur` 远小于 `audio_dur` | **循环 loop / 定格 still**：循环播放或末帧定格补足 | `loop` 滤镜 / `tpad=stop_mode=clone` |
| 用户指定 | 手动选择适配方式 | 按选择执行 |

- 适配优先级默认：`trim` → `slow`（限幅内）→ `loop/still`
- 每行适配方式在 SD-3 表格可视化，用户可手动改
- 限幅参数可配置：`slow_max_ratio`（默认 1.5）、是否允许 loop

### 6.4 合成管线（ffmpeg）

```
逐行生成适配片段：
  对每行 i：取 clip_i → 按 adapt_mode 调整到 clip_dur_i → 输出 seg_i.mp4（统一分辨率/帧率/像素格式）

拼接：
  seg_0 .. seg_n 用 concat（或带 xfade 转场，复用 _concat_with_transition）→ video_track.mp4

配音轨：
  逐行 wav 按全局 t_start 排布（句间 gap）→ 拼接为 voice_track.wav（复用 _concat_wav_bytes）

混音 + 烧字幕：
  video_track + voice_track + BGM（amix + 人声闪避，复用 FinalMixWorker）
  + 字幕（由 .timing.json 生成 SRT/ASS，复用 VideoDubbingWorker）
  → 成片
```

### 6.5 字幕对轴

- 复用 `VoiceCloneWorker` 产出的 `.timing.json`（每句 start/end）
- 按全局时间轴偏移生成 SRT/ASS，确保字幕与配音逐句同步
- 字幕样式沿用现有 `VideoDubbingWorker` 配置

## 十、风险与对策

| 风险 | 对策 |
|------|------|
| 镜头普遍短于文案音频时长 | 限幅降速 + loop/定格补足；文案生成阶段按时长约束字数（GenScriptWorker 已支持） |
| 镜头数少于文案行数 | 允许去重受限的复用，避免相邻重复；提示用户补充素材或精简文案 |
| LLM 匹配不稳定 | CLIP 交叉验证 + 顺序兜底 + 手动改配 |
| 合成卡死（移动盘 I/O） | 复用现有合成看门狗 + 预拷贝本地临时目录（concat_workers 已有） |
| 误改现有流程 | 全部新增 `sd_` 前缀文件 + 独立控制器，现有 step1~step4 与 VideoMontagePage 零改动 |
| TTS 逐行耗时较长 | 并发限流 + 进度可视 + 单行失败不中断整批（VoiceCloneWorker 已有容错） |

## 十一、验收要点

- [ ] 现有「成片优先」流程回归无变化（零改动验证）
- [ ] 新流程可完整走通：素材→分割→文案→音视频→合成出片
- [ ] 文案编辑/增删/排序后，音视频随之更新
- [ ] 每行配音时长驱动对应镜头时长，成片音画同步
- [ ] 字幕与配音逐句对齐
- [ ] 手动改配镜头生效且被锁定
- [ ] 镜头不足/过短场景的降级策略正常
