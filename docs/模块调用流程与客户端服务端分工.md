# 模块调用流程与客户端/服务端分工

- 版本：v2.0 | 更新：2026-08-01（由 v1.0 docx 迁移为 Markdown 权威版本，原 docx 保留为历史参考）
- 服务端统一地址：由 `studio/config/ai_config.json` 的 `compute_server_url` 配置（当前 `http://192.168.111.28:8000`）
- 接口契约权威来源：服务端 `/guide`（实际命名/参数/返回格式以 /guide 为准）

## 一、决策原则

1. **重模型 / 大 GPU / 大文件编解码 → 服务端**：避免客户端机器性能差异导致输出不一致，统一 10-bit/高画质转低画质等编码策略。
2. **交互 / 浏览 / 预览 / 本地数据管理 → 客户端**：保证响应速度和离线可用性。
3. **外部工具（Dreamina、Remotion）**：按部署情况决定，服务端有环境则优先迁服务端。
4. **轻量本地计算**（镜头去重哈希、时长探测、抽帧）可留客户端，避免网络往返。

## 四、高优先级迁服务端建议

| 功能模块 | 迁服务端理由 |
|---|---|
| 视频 LUT 转换 | 统一输出质量，避免客户端 GPU 差异（本地 LUT 调色功能已删除，随混剪 LUT 走服务端） |
| 一键成片 | 本地 ffmpeg 合成图片/音频；迁服务端统一编码参数、降低客户端负载 |
| 图层化生图 | 本地 Qwen Diffusers 对客户端 GPU 要求高且不稳定；建议全部迁服务端 |
| 镜头分割 | 本地 PySceneDetect 分割后还需上传；迁服务端（/montage/split 已就绪）可减少上传流量 |
| MG 动画 | 本地 Node/Remotion 渲染；服务端部署 Node 后迁 |
| 混剪最终混音/烧录 | 本地 ffmpeg 混音；可与镜头拼接统一输出 |

## 五、后续行动建议

1. 对高优先级模块逐个出接口改造方案，优先：一键成片、混剪最终混音/烧录。
2. 镜头分割迁服务端后，服务端直接返回分割片段，客户端只做列表展示与确认。
3. 图层化生图整体迁服务端，客户端仅上传图片与预览。
4. 保留客户端本地 ffmpeg 作为离线 fallback，默认全部走服务端。
5. 服务端 /guide 持续补充新增接口，客户端按 /guide 对齐。

## 六、分镜脚本服务端存储（专项，见 PRD_V2.2 第七章）

- **需求**：分镜脚本从客户端本地 JSON 迁移到服务端存储，多端可见/可备份/可协作；「一键成片 → 脚本成片」直接读取服务端脚本列表。
- **现状核对（2026-08-01）**：
  - 服务端 `/guide` 已有「分镜脚本成片」接口：`POST /scheduled/tasks`，`task_type=storyboard_montage`，`params.shots[]`（服务端自动搜素材→TTS→FFmpeg→质量评分），客户端提交后轮询 `/tasks/unified/{id}`。
  - 服务端 `/guide` **尚无**「分镜脚本存储/列表」接口（规划 `/api/storyboard/scripts` CRUD），该部分仍为 PRD 规划，待服务端实现后补充 /guide。
- **客户端现状**：`storyboard_page` 保存时本地导出 Excel/JSON；JSON 供「一键成片 → 脚本成片」本地扫描使用；服务端存储接口就绪后切换为服务端读写，本地保留为离线缓存。
