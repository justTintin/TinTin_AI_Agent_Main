# 多智能体编排服务端接口需求

> 来源：PRD_V2.2.md 第十三章（多智能体编排/服务端智能体化）
> 目的：服务端先行「智能体化」——能力可注册、可编排、可多端共享调度。
> 提交方式：按服务端 /guide「POST /interfaces/request 提交新接口需求」契约封装为 JSON 提交；实现后补充 /guide 文档。

## 需求总览

| # | 接口 | 方法 | 优先级 | 状态 |
|---|------|------|--------|------|
| S1 | `/agent/registry` | GET | P0 | 待提交 |
| S2 | `/agent/tasks` | POST | P1 | 待提交 |
| S3 | 子任务模型（`/tasks/unified` 扩展） | - | P0 | 待提交 |
| S4 | `/agent/tasks/{id}/confirm` | POST | P1 | 待提交 |
| S5 | 中间产物登记 | POST | P1 | 待提交 |
| S6 | 编排任务管理（列表/暂停/取消/重试） | GET/POST | P1 | 待提交 |

## S1 能力注册表（P0）

- `GET /agent/registry`：返回全部可编排能力清单。
- 能力字段（schema）：

```json
{
  "id": "tts_voice_clone",
  "name": "声音克隆/TTS",
  "description": "输入文案+参考音频，返回克隆语音",
  "executor": "server",            // server | client_tool | external
  "api": "POST /voxcpm/tts",
  "input_schema": {"text": "string", "prompt_audio": "base64", "speaker": "string"},
  "output": {"audio": "file_ref"},
  "sync": true,
  "needs_user_input": false,
  "dependencies": []
}
```

- 期望覆盖：LLM、TTS、ASR、素材检索/分析、视频处理（split/concat/beat/vsr）、成片任务、ComfyUI 等（以 /guide 为准）。

## S2 提交编排任务（P1）

- `POST /agent/tasks`：提交 plan（推荐）或自然语言（服务端拆解）。
- plan 为可序列化 JSON：`{steps: [{capability, params, depends_on, needs_user_input}], ...}`
- 返回 `task_id`（进入现有 /tasks/unified 轮询体系）。

## S3 子任务模型（P0）

- 任务增加 `parent_task_id`，支持父子任务树。
- `/tasks/unified/{id}` 返回树状状态：`{task, children: [...]}`。
- 父子进度聚合：父任务状态由子任务推导（pending/running/waiting_user_input/done/failed）。

## S4 人工确认节点（P1）

- 子任务状态 `waiting_user_input`（如选素材、确认文案、试听音频）。
- `POST /agent/tasks/{id}/confirm` 提交用户确认结果后继续执行。

## S5 中间产物登记（P1）

- 子任务产物（音频/视频/图片）在服务端登记 `file_ref`（路径/URL + 元数据），供下游步骤引用，避免重复上传。

## S6 编排任务管理（P1）

- 列表：`GET /agent/tasks?status=...`
- 暂停/取消/重试：`POST /agent/tasks/{id}/pause|cancel|retry`
- 断点续跑：任务状态持久化，不依赖客户端在线。

## 验收

- S1 就绪后：客户端能拉到统一能力清单，展示"服务端当前有多少可编排智能体"。
- S2/S3 就绪后：服务端可执行一份 plan，多端共享、断点续跑、失败重试。
- S4/S5 就绪后：支持"跑一半等用户确认"与下游引用中间产物。
